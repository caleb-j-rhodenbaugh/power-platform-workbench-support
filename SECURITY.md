# Security reporting

Do not publish suspected vulnerability details, credentials, access tokens, signed URLs, customer data or private deployment artifacts in issues, comments or attachments.

Use [Report a vulnerability](https://github.com/caleb-j-rhodenbaugh/power-platform-workbench-support/security/advisories/new) to submit a private security report to the maintainer. Include a minimal synthetic reproduction and affected extension version. Do not include real credentials or customer data, even in a private report.

If a credential has already been exposed, revoke or rotate it through its owning service and remove public copies where possible. Deleting an attachment does not guarantee that it was not copied.

The extension's release notes and Marketplace version identify available releases. No response-time guarantee or external security certification is claimed. Public issues should contain only ordinary, sanitized product defects; security reports require a separate private channel.
