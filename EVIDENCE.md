# Local evidence ownership and retention

Evidence records share the existing `RecordStore` envelope in `workbench-core.js`: `schemaVersion`, `id`, `bucket`, `workspaceRoot`, UTC `savedAt`, and domain `data`. Presets, change sets, snapshots, job receipts and deployment/check history use that envelope. UI timestamps use the shared machine date/time formatter. Stable IDs and captured account/environment identities are authoritative; display labels are not.

| Evidence | Owner and lifetime | User control |
| --- | --- | --- |
| Active diagnostic results | Each tool tab retains up to 24 results or 8 MiB of result content/tables, evicting oldest results first. The newest result is always retained even if it exceeds that size. Mounted pages are not the evidence boundary: MCP and export can read all rows of each retained result. The active surface is transient; the separate tool-history capture below persists supported result evidence. | Select a retained result, restore a capture through History, export, clear results or close the tab. Clearing the active surface does not delete persistent history. Exported copies belong to the chosen folder. |
| Editable query/import grids | Owned by their result session, separate from the diagnostic result limit above. | Export the current data, release an agent-owned grid to the human, or close its session. Saving a query saves its definition, not its returned records. |
| File/data Diff | Exact review; keep failure/incomplete evidence. Confirmed final success, close or replacement releases owned temporary artifacts. | Review checked subset; fresh Diff is required after an uncertain write. Never resubmit automatically. |
| Presets/change sets | Workspace `RecordStore`, no automatic expiry. They are saved user work. | Saved Work reopens and revalidates the exact captured scope. Comparison Evidence creates/exports them. |
| Comparison snapshots | Workspace record plus hash-bound retained artifact directory. | Saved Work → snapshot offers Remove saved reference or reviewed Delete retained cache. Removing a reference does not silently delete its cache. |
| Deployment/check/job receipts | Workspace `RecordStore`, no automatic expiry. Stage outcomes and IDs remain distinct. | Deployment History or Inspect Server Jobs displays and exports evidence; monitoring does not resubmit a write. |
| Tool result history | Workspace/account/environment/solution-bound RecordStore, retained across restarts. Full evidence is chunked without row truncation; callbacks and write authority are excluded. | History in the owning tool restores read-only results; Clear result history removes those local captures. Diff Content has no history. |
| Saved selections | Workspace/account/environment/solution-bound form values. Password, hidden authority and read-only fields are excluded. | Save selections / Saved selections in the tool; restore revalidates current schema and does not submit. Query Data keeps its existing query-definition store. |
| Saved/recent queries | Workspace/account-bound definition stores; recent list bounded to six. | Query Data → Saved Queries manages named definitions; History opens recent definitions and captured results. Result records are not saved with a definition. |
| Component recovery | Separate versioned recovery manifest with exact component/data hashes and expiry. It must not be flattened into a diagnostic row. | Component Recycle Bin and Settings → Deploy → retention days, default 30. Expiry removes only owned local recovery copies. |
| Metadata cache | Account/tenant/cloud/connection/workspace-scoped transient reads; bounded and coalesced. | Metadata cache minutes preference; Expired metadata reloads automatically; explicit tool operations validate identity. Failed reads are not cached as success. |

Do not apply recovery expiry to saved user work, or call a read-only result a writable record. Generic results say **Read-only** and copy/export local evidence; Query Data and import results retain their distinct reviewed record-editing actions. Open JSON opens a local diagnostic copy; Edit JSON belongs to editable record workflows. Sensitive callback/settings values use private review and must not enter general evidence or MCP results.

Shared operation metadata reports `preparing`, `running`, `awaitingInput`, `manualRequired`, `completed`, `cancelled`, `failed`, or `incomplete`. UI busy state comes from the active operation, not a previous error. Incomplete means the exact outcome is not established; it is never a retry instruction or proof that nothing changed. Existing surface state fields remain compatible while the common `operation` object supplies consistent semantics.

The shared operation helper retains the innermost named failure stage and original error code. Review destination projections contain only captured, allowlisted identity fields; they do not read current defaults or expose credentials. An updated default cannot change an existing review's authority. Result action effects and eligibility come from the host and are projected to both the browser and MCP.

Native agent handoff evidence checks rendered drafts, row selections and retained Settings values, in addition to host session state. VS Code forwards native messages through its same-origin parent; the shared bridge rejects foreign, opaque and authored child-frame messages. Showing a session clears only the renderer's initial preparing state, restores retained state and never reruns or saves the operation.

Workflow acceptance declarations identify the production handlers, exact branches and asserted lifecycle dimensions. They are fixture descriptions, not successful-run receipts. Local suites share one host and assertion library, record completed scenario IDs separately, and combine their receipts only when every declared scenario has passed. The release evidence directory retains those receipts alongside `workflow-acceptance.json`; an interrupted collection never creates a passed aggregate. Mocked handler checks do not certify real credentials, service behavior or rendered browser/native accessibility.

Disk/process failure can leave temporary artifacts. These policies are not secure-erasure guarantees; see [Privacy](PRIVACY.md). Storage cleanup never deletes source or exported files without their established explicit workflow.
